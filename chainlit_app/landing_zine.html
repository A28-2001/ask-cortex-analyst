I built Ask Cortex Analyst, a thing you can type plain English at and get real answers out of a Snowflake warehouse. Then I spent a while trying to break it, because the interesting question is not whether it works on easy questions. It is what it does when it cannot possibly know the answer.

So I ran a control. Two systems, same warehouse, same 44 questions, same rubric, written down before either of them ran. One got a documented semantic model. The other got raw table names and had to guess.

how it works

The difference is not a smarter model

It is what you put between the model and the warehouse.

1

The warehouse

500 customers, 18 months of SaaS subscription data, modelled in dbt on Snowflake into tested tables: MRR movements, cohort retention, health scores, anomaly flags.

2

The semantic model

A YAML file describing all of that in business language. Synonyms, the actual valid values of every category, verified example queries, and explicit rules about what to refuse.

3

Question to SQL

Cortex Analyst writes the SQL using that context. The baseline got table and column names and nothing else, running on Llama 3.3 70B via Groq.

4

Running it

A Chainlit app executes the SQL and renders the answer, always showing the query it ran. If a query comes back empty, it explains why instead of showing you an empty box.

What this does not prove

Putting this up front because I think the caveats are more interesting than the headline number.

  • That 100% came after I fixed things. The first clean run was 93.1%. I found three failure modes, a guardrail gap, a calculation it left half done, and a schema bug I had introduced myself, fixed each, and re ran. Scoring perfectly on the set you used to find the bugs is a weaker claim than it sounds.
  • The holdout is the honest part. Eight questions written after all the fixes, never used for tuning, including a customer ID that does not exist and a metric I made up. Eight out of eight. Still only eight questions.
  • The fair single pass comparison is 65.3 against 93.1, because the baseline was run cold once and never tuned. Comparing it to the fixed up 100 would be flattering myself.
  • It is one baseline model with one plain prompt. Someone could hand write a prompt that reinvents half a semantic layer and score better. This is what the lazy version gets you, which is the version most people actually ship.
