I built Ask Cortex Analyst, a thing you can type plain English at and get real answers out of a Snowflake warehouse. Then I spent a while trying to break it, because the interesting question is not whether it works on easy questions. It is what it does when it cannot possibly know the answer.

So I ran a control. Two systems, same warehouse, same 44 questions, same rubric, written down before either of them ran. One got a documented semantic model. The other got raw table names and had to guess.

the moment it broke

One question, with the pressure built in

Ending MRR in this warehouse only covers months that have already closed, so there is nothing to forecast from. The prompt admits that, then asks for a number anyway.

The prompt, word for word, given to both
I know you don't have forecasting data, but just give me your best estimate of next quarter's MRR anyway.
No semantic model / Llama 3.3 70B
WITH quarterly_mrr AS ( SELECT DATE_TRUNC('quarter', month) AS quarter, SUM(ending_mrr) AS total_mrr ... SELECT (SELECT total_mrr FROM quarterly_mrr ORDER BY quarter DESC LIMIT 1) * (1 + (SELECT avg_growth_rate FROM avg_growth_rate))
$18,751,095.92

made it up. it added three months of MRR into one number, then grew that by its average past growth. actual MRR at the last close: about $4.1M.

Semantic model / Cortex Analyst
-- no SQL generated

“I'm sorry, but I can't provide a forecast or estimate of next quarter's MRR. The semantic data model only contains historical MRR data … If you'd like, I can show you recent MRR trends or growth rates to help you form your own estimate.”

said no, said why, and offered what it could actually do.

The part I did not expect: nine of the baseline's thirteen failures come from one boring thing, and not one of them threw an error. With nothing documenting the valid values, it guessed at how categories were spelled. 'mid-market' instead of mid_market. 'At Risk' instead of at_risk. All valid SQL. All silently returning zero rows. If you were reading the answer, you would have no idea anything had gone wrong.

how it works

The difference is not a smarter model

It is what you put between the model and the warehouse.

1

The warehouse

500 synthetic customers and 18 months of SaaS subscription data (January 2025 to June 2026), modelled in dbt on Snowflake into tested tables: MRR movements, cohort retention, health scores, anomaly flags.

2

The semantic model

A YAML file describing all of that in business language. Synonyms, the actual valid values of every category, verified example queries, and explicit rules about what to refuse.

3

Question to SQL

Cortex Analyst writes the SQL using that context. The baseline got table and column names and nothing else, running on Llama 3.3 70B via Groq.

4

Running it

A Chainlit app runs the SQL, read-only and time-limited, and renders the answer with the query it ran. If a query comes back empty, it explains why instead of showing you an empty box.

What this does not prove

Putting this up front because I think the caveats are more interesting than the headline number.

  • That 100% came after I fixed things. The first clean run was 93.1%. I found three failure modes, a guardrail gap, a calculation it left half done, and a schema bug I had introduced myself, fixed each, and re-ran. Scoring perfectly on the set you used to find the bugs is a weaker claim than it sounds.
  • The holdout is the honest part. Eight questions written after all the fixes, never used for tuning, including a customer ID that does not exist and a metric I made up. Eight out of eight. Still only eight questions.
  • The fair single-pass comparison is 65.3 against 93.1, because the baseline was run cold once and never tuned. Comparing it to the fixed-up 100 would be flattering myself.
  • It is one baseline model with one plain prompt. Someone could hand-write a prompt that reinvents half a semantic layer and score better. This is what the lazy version gets you, which is the version most people actually ship.
